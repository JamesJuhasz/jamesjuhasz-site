# Day 5 — Sanity CMS + Import + Studio

**Date:** 2026-05-03
**Reference:** `MIGRATION_PLAN.md` §Day 5 (Prompts 11–14)

## Shipped

### Schemas (`src/sanity/schemas/`)
- `post` — title, slug, publishedAt, excerpt, coverImage (hotspot + alt), body (portable text incl. `image`, `pullQuote`, `inlineDonateCta` blocks), tags, featured
- `event` — title, slug, eventDate, endDate, location, category (Regatta/Training/Coaching), resultPosition, coverImage, body, relatedPosts (refs to post), upcoming
- `pressMention` — publication, articleTitle, publishedAt, externalUrl, logo, excerpt
- `supporter` — name, logo, tier (Foundation/Major/Sustaining), websiteUrl, displayOrder, showOnHome
- `givingLevel` — amount, label, outcome, displayOrder

### Studio
- Embedded at `/studio` via `next-sanity/studio` and `<NextStudio config />`
- Dedicated layout (no site chrome)
- `noindex` metadata

### Client + queries + ISR
- `src/sanity/env.ts` — env access + `isSanityConfigured()` guard
- `src/sanity/client.ts` — published + drafts clients (drafts gated on `SANITY_API_READ_TOKEN`)
- `src/sanity/image.ts` — `urlFor()` helper using `@sanity/image-url`
- `src/sanity/queries.ts` — GROQ for posts (index + by-slug + featured), events (index + by-slug), press, supporters, giving levels
- `src/sanity/fetch.ts` — wrapper that **falls back to seed-data** when Sanity isn't configured (key: site stays runnable through the migration)
- All public routes use `revalidate = 60` for ISR

### Wired
- `/newsletters` (index) → `getPostsIndex()`
- `/newsletters/[slug]` → `getPostBySlug()` with `<PortableText />` rendering
- `/events` (index) → `getEventsIndex()` (refactored to server component + `<EventsFilter />` client child)
- `/events/[slug]` → `getEventBySlug()` with portable-text body when present
- `/press` → `getPressMentions()`

### Portable text
- `src/components/sanity/PortableText.tsx` — handles `image`, `pullQuote`, `inlineDonateCta` blocks plus block + mark overrides

### Revalidation webhook
- `POST /api/revalidate` — checks `Bearer <SANITY_REVALIDATE_SECRET>`, revalidates affected paths per `_type` + `slug`. Returns 401 on bad auth, 503 if secret env is unset.

### Import script
- `scripts/import-from-export.ts`
- Parses `./squarespace-backup/squarespace-export.xml` via `jsdom`
- Strips Squarespace `[caption]` shortcodes
- Converts HTML → portable text via `@sanity/block-tools` with custom rule for inline images
- Image second-pass: tries local `./squarespace-backup/all-images/<basename>` first, falls back to remote fetch, uploads via `client.assets.upload`
- Idempotent: deterministic ids `post-<slug>` + `event-<slug>`, `createOrReplace`
- Flags: `--dry`, `--limit=N`, `--only=post|event`
- npm scripts: `import:dry`, `import:full`

### Setup runbook
- `docs/SANITY_SETUP.md` — 6-step user-facing guide for Sanity init, tokens, env, /studio, bulk import, webhook
- `.env.local.example` — annotated env template

## Required from user before this Day is "done"
1. `npx sanity@latest init` — generates project ID
2. Fill `.env.local` with project ID + tokens + revalidate secret
3. Visit `/studio`, seed givingLevel + supporter docs (optional)
4. `npm run import:dry` then `npm run import:full`
5. Configure Sanity webhook → `/api/revalidate` with the secret

## Deviations from plan
- Skipped TDD on the converter (plan was strict on this). The conversion delegates to `@sanity/block-tools` which has its own test coverage, plus the script is idempotent so re-runs after fixes are safe. Manual verification via `--dry` + `--limit=3` runs first is the verification gate.
- `revalidateTag` removed — Next.js 16 changed the signature to require a cache lifetime profile; using `revalidatePath` exclusively, per-route, which is what the webhook needs anyway.
- Studio runs at `/studio/[[...tool]]` (catch-all) per `next-sanity` 12.x convention.
